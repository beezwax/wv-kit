# wv-kit

Dev server and build pipeline for [FileMaker web viewer](https://help.claris.com/en/pro-help/content/defining-web-viewers.html) projects. Write your viewer as a normal ES module project; wv-kit compiles it to a single self-contained HTML file ready to paste into FileMaker.

## What it does

- **Dev server** — live-reloads viewer pages, mocks FileMaker script calls, relays callbacks over SSE
- **Build** — Vite + `vite-plugin-singlefile` bundles every viewer to one inline HTML file
- **ESLint plugin** — catches patterns that don't work in a FileMaker web viewer (navigation via `window.location`, bare imports, missing default export, etc.)
- **TypeScript / JSX / TSX** — auto-transformed by esbuild in dev; Vite handles production

## Install

```bash
npm install wv-kit
npm install eslint   # required peer dependency
```

## Project structure

```
src/
  shared/
    style.css             # @import Bootstrap from CDN
    filemaker-scripts.js  # outbound FM script calls
    script-names.js       # FM script name constants
    installed/            # auto-generated by wv-kit install — never edit
  <viewer>/
    index.js              # entry — default export is the app element
    view.js               # builds and returns the DOM tree
    control-functions.js  # inbound FM callbacks (window.load*, window.onSave*, …)
    dev/
      client.js           # seeds initial data in dev
      data.json           # mock data read/written by mocks.js
dev-server/
  mocks.js                # server-side FM script handlers
front-end-dependencies/
  <pkg>.js                # re-export entry for a browser-bundled npm package
```

## Commands

| Command | What it does |
|---|---|
| `wv-kit start` | Start the dev server on port 3000 |
| `wv-kit build [viewer…]` | Build one or all viewers → `dist/*.html` |
| `wv-kit check` | Run ESLint only (same as the lint step in `build`) |
| `wv-kit install` | Bundle `front-end-dependencies/` → `src/shared/installed/` |

`wv-kit build` runs ESLint before building and exits 1 on errors. On macOS the single-viewer form copies the output to the clipboard automatically.

## Viewer contract

`index.js` must export the app element as its default. wv-kit appends it to `#app` and then fires any `onMount` callbacks.

```js
// src/my-viewer/index.js
import { onMount } from 'wv-kit';
import controlFunctions from './control-functions.js';
import buildApp from './view.js';

Object.assign(window, controlFunctions);
onMount(() => {
  // element is in the DOM here
});
export default buildApp();
```

## FileMaker communication

| Direction | Mechanism |
|---|---|
| Browser → FileMaker | `window.FileMaker.PerformScriptWithOption(name, json, 0)` |
| FileMaker → Browser | FileMaker calls a global, e.g. `window.loadData(jsonStr)` |

Wrap all outbound calls in `src/shared/filemaker-scripts.js` and keep script name strings in `src/shared/script-names.js`. Calls made before FileMaker sets `window.FileMaker` are queued and replayed automatically.

```js
// dev-server/mocks.js — simulate both directions in dev
import { performJavaScriptInWebViewer } from 'wv-kit/lib/sse.js';
import { scriptNames } from '../src/shared/script-names.js';

export default {
  [scriptNames.loadRecords]: () => {
    performJavaScriptInWebViewer('loadData', JSON.stringify(records));
  },
};
```

## Browser dependencies

Direct `import { x } from 'some-package'` doesn't work in the browser. Pre-bundle packages via `front-end-dependencies/`:

```js
// front-end-dependencies/my-lib.js
export { Chart } from 'chart.js';
```

Then import from the generated bundle:
```js
import { Chart } from '../shared/installed/my-lib.js';
```

Run `wv-kit install` after changing these files. Place a `.d.ts` file alongside the `.js` entry to provide TypeScript types for the bundle.

## ESLint

`wv-kit build` runs ESLint automatically. For IDE inline errors, add a one-line config:

```js
// eslint.config.js
export { default } from 'wv-kit/eslint.config.js';
```

### Adding to an existing config

Import the plugin and spread the recommended config into the entry that covers `src/`:

```js
// eslint.config.js
import wvKit from 'wv-kit/lib/eslint.js';
import someOtherPlugin from 'some-other-plugin';

export default [
  // your existing rules
  {
    files: ['src/**/*.js'],
    plugins: { 'some-other': someOtherPlugin },
    rules: { 'some-other/rule': 'error' },
  },

  // spread wv-kit's two config objects (rules + dev/ exception)
  ...await import('wv-kit/eslint.config.js').then(m => m.default),

  // or add only the rules you want
  {
    files: ['src/**/*.js'],
    plugins: { 'wv-kit': wvKit },
    rules: {
      'wv-kit/no-window-location':    'error',
      'wv-kit/no-anchor-href':        'error',
      'wv-kit/no-bare-import':        'error',
      'wv-kit/no-dev-outside-import': 'error',
      'wv-kit/index-default-export':  'error',
    },
  },
  {
    // window.location is allowed in dev/ files
    files: ['src/**/dev/**'],
    rules: { 'wv-kit/no-window-location': 'off' },
  },
];
```

`no-dev-outside-import` accepts an `allow` array for imports that are intentionally outside `dev/`:

```js
rules: {
  'wv-kit/no-dev-outside-import': ['error', {
    allow: ['../shared/filemaker-scripts.js'],
  }],
}
```

Rules included:

| Rule | What it catches |
|---|---|
| `no-window-location` | `window.location` in production code |
| `no-anchor-href` | `<a href="…">` used for navigation |
| `no-bare-import` | bare npm specifiers in `src/` |
| `no-dev-outside-import` | dev files importing viewer internals |
| `index-default-export` | `src/*/index.js` missing a default export |

## TypeScript

The dev server transforms `.ts`, `.tsx`, and `.jsx` on the fly. Add `allowJs: true` and `checkJs: false` to `tsconfig.json` to allow importing plain JS from typed files.

Declare types for bundled front-end dependencies by placing a `.d.ts` file alongside the entry in `front-end-dependencies/` — it is copied to `installed/` automatically.

## Production constraints

FileMaker web viewers are single HTML files with no URL routing. Keep production code free of:

- `window.location` reads or writes — use `filemakerScripts.navigate*()` instead
- `<a href="…">` — use `<button>` with a click listener
- Bare npm imports — bundle via `front-end-dependencies/`

`dev/` files are excluded from these rules and may read `window.location` to seed initial data.
